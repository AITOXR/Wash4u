# Wash4You Website

Static site for **Wash4You** (`https://wash4you.in`) — eco-friendly laundry, dry
cleaning and specialist fabric care in Gurugram.

Generated with Python + Jinja2 and deployed on GitHub Pages. Every page is
pre-rendered HTML, which is why the site can carry ~110 SEO landing pages at
zero hosting cost.

## Structure

```
src/
  data/            JSON content — edit these to change copy
    generated/     AI-generated SEO copy (services, localities, matrix)
  templates/       Jinja2 templates
  assets/
    css/           base → layout → ui → page → features → animations  (load order matters)
    js/            GENERATED bundle — do not edit
    images/
      pricing/     per-item product photos for the pricing grid
    wash4you-price-list.pdf   GENERATED by tools/make-pdf.mjs — do not hand-edit
  js/              JS SOURCE — edit here
    cart.js        the pickup-list ("cart") → WhatsApp booking handoff
    motion/        the Motion (motion.dev) animation layer
  build.py         the generator
tools/
  shot.mjs         screenshot + layout/a11y audit across 3 viewports
  make-pdf.mjs     renders pricing-print.html → src/assets/wash4you-price-list.pdf
dist/              build output (gitignored)
```

`features.css` holds the components added in the client-feedback pass: the top
utility bar, the header mega-dropdowns, the pickup-list cart, the home banner,
the "Why Wash4You" / 7-step / blog sections, the pricing image grid, and
packages. It loads after `page.css` so it can layer on the base system.

## Build

Content-only change (no Node required):

```bash
python3 src/build.py
```

Full build, including the JS bundle:

```bash
npm install        # once
npm run build      # build:js + build.py
```

`npm run build:js` bundles `src/js/main.js` (and Motion, tree-shaken) into
`src/assets/js/main.js` as a minified IIFE — about 7 KB gzipped. That output is
committed, which is why a content-only edit does not need Node.

### The price-list PDF

The "Download PDF" button on `/pricing/` serves `assets/wash4you-price-list.pdf`,
generated from `pricing.json` (via the `pricing-print.html` template) so it can
never drift from the on-page rates. Regenerate it after changing prices:

```bash
python3 src/build.py                                   # rebuild, incl. pricing-print.html
python3 -m http.server 8099 --directory dist &         # serve
npm run build:pdf                                       # writes src/assets/ + dist/assets/
```

## Preview

```bash
python3 -m http.server 8099 --directory dist
```

Then `http://127.0.0.1:8099/`.

To screenshot and audit (needs Chrome installed):

```bash
node tools/shot.mjs http://127.0.0.1:8099 ./shots / /services/ /pricing/
```

It reports horizontal overflow, console errors, H1 count, missing alt text and
sub-44px tap targets at 390 / 834 / 1440px.

## Deploy

`dist/` is copied to the repo root, which is what GitHub Pages serves.

```bash
python3 src/build.py
rsync -a \
  --exclude '.git' --exclude 'src' --exclude 'docs' --exclude 'webapp' \
  --exclude 'wash4y' --exclude 'node_modules' --exclude 'tools' \
  dist/ .
```

The easiest way to publish, though, is the local admin (`python3 src/admin/server.py`)
— its **Publish** button runs this exact overlay for you.

> Do **not** add `--delete-excluded`: it overrides the excludes and would wipe
> `src/`, `wash4y/`, `webapp/` and friends from the repo root. The previous
> instruction `rm -rf dist/* && cp -R dist/* .` was also wrong — it deletes the
> build before copying it. Use the plain overlay above (no `--delete`).

`wash4y/` (the React booking app, built from `webapp/`) is deployed separately
and must not be deleted by a site deploy.

## Content

All copy lives in `src/data/*.json`:

| File | Contents |
|---|---|
| `site.json` | brand, nav, footer, contact, stores, the four promises, locality URL map |
| `home.json` | homepage copy and FAQs |
| `services.json` | the 15 services |
| `proof.json` | before/after pairs and the pickup process |
| `testimonials.json` | real customer quotes and photographs |
| `locations.json`, `pricing.json`, `policies.json`, `blog.json`, `about.json`, `pages.json` | the rest |
| `generated/` | long-form SEO copy for services, localities and the service×locality matrix |

### Rules for this site's content

1. **Never publish a claim the client cannot substantiate.** A fabricated
   aggregate rating is a Google manual-action risk. The removed claims are
   recorded in the `_removed` key of `home.json`.
2. **Never invent a customer name.** Only "Pranav Ji" was named by the client;
   everyone else is "Verified Customer". See `_source` in `testimonials.json`.
3. **`docs/` is client-supplied source material (~2.2 GB) and must stay
   untracked.** Several videos exceed GitHub's 100 MB file limit.

## Motion

`src/js/motion/` is the animation layer, built on
[Motion](https://motion.dev) (`motion/mini` — the WAAPI build). Read
`src/js/motion/tokens.js` first: it is the whole vocabulary, and nothing may
animate with a number that is not in it.

Guarantees, all verified in `tools/shot.mjs` runs and a headless probe:

- **No JS** → nothing is ever hidden (`html.js` gates every hidden state).
- **JS but no bundle** → a CSS `motion-failsafe` keyframe un-hides everything
  at 1400ms.
- **`prefers-reduced-motion`** → `html.motion-off`, everything visible, nothing
  moves. `?noanim` takes the same path for QA.
- Hidden state is **opacity only**, never transform, so a failure can fade
  content but can never strand it at an offset.
